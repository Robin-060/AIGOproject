## 1. 项目概述

### 1.1 一句话定位

> 面向 OBS 地震数据处理的**模型无关可靠性调度层**——综合数据质量、多模型分歧与流程证据，评估 AI 拾取结果的可靠性，决定自动接受、模型融合或人工复核。

### 1.2 电梯演讲 (30秒版)

我们不再开发一个新的 OBS 拾取模型，而是在所有模型之上做一个可信 AI 调度层。系统检查数据质量、比较不同模型的 P/S 拾取、评估风险，把低风险结果自动送入后续流程，把高风险样本交给专家复核。创新由真实 OBS 数据、真实模型和基线对比来验证。

### 1.3 核心创新

| 现有方案 | 我们的方案 |
|----------|------------|
| 模型直接输出 → 全自动处理 | 模型输出 → **可靠性评估** → 选择性自动处理 |
| 单一模型，错了就错了 | 多模型交叉验证，分歧 = 风险信号 |
| 置信度 = 信任度 | 置信度只是证据之一，需结合数据质量、模型一致性、物理约束 |
| 对所有样本强行给答案 | **允许 AI 说"我不确定"，拒绝不可靠预测** |

## 2. 问题定义

### 2.1 行业背景

海底地震仪（OBS）是深海板块运动、热液活动、海底地质灾害研究的核心观测设备。OBS 长期连续采集海量一维振动时序波形，但深海环境叠加多重干扰：

- 洋流长周期噪声
- 仪器电气耦合干扰
- 热液持续微震
- 原始波形信噪比极低

### 2.2 核心痛点

| 痛点 | 现状 | 影响 |
|------|------|------|
| **人工解译效率极低** | 传统 STA/LTA 算法对深海噪声适配性差，需人工逐道拾取 P/S | 单航次数据解译耗时数月 |
| **模型不可靠** | 深度学习模型在陌生海域、异常噪声下会高置信地犯错 | 错误拾取污染后续关联和定位 |
| **缺乏可靠性机制** | 现有模型只输出"在哪里"，不输出"可不可信" | 用户无法判断何时该信任模型 |
| **工程化缺失** | 学术模型仅有论文代码，无完整工具链 | 小型海洋实验室无法落地使用 |

### 2.3 典型故障场景

| 场景 | 模型行为 | 后果 |
|------|----------|------|
| 数据缺一个通道 | 模型强行推理，score 0.88 | 错误被当作正确接受 |
| 陌生海域部署 | 遇到训练时未见过的噪声模式 | 乱报虚检 |
| 三个模型给三个不同答案 | 没有一个模型能判断谁对谁错 | 用户不知道该信谁 |
| P 波拾取晚于 S 波 | 模型违反物理规律仍高置信 | 物理上不可能的结果进入地震目录 |

## 3. 目标与成功标准

### 3.1 科学目标

构建面向深海低信噪比 OBS 数据的 AI 可靠性评估框架，实现：

1. **风险可量化**：对每次 AI 拾取输出结构化风险等级
2. **错误可拦截**：高风险样本被标记为"需人工复核"，避免错误流入后续流程
3. **决策可解释**：每次决策附带 reasons code，说明为什么接受/拒绝
4. **基准可复现**：建立标准化评测框架，与单模型、最高置信度、简单投票等基线对比

### 3.2 工程目标

1. 开发一套**纯本地离线运行**、轻量级 CPU 可推理的开源工具链
2. 接入至少 2 个真实拾取模型（OBSTransformer + PhaseNet）
3. 提供 Web 可视化面板（波形 + 多模型标记 + 风险报告）
4. 一键复现脚本 + 完整 README + 部署文档

### 3.3 开源目标

1. 全代码开源（MIT License）
2. 配套完整文档、实验日志、评测结果
3. 开源数据集（公开 OBS 数据 + 仿真生成数据）

### 3.4 量化成功标准

> **"在自动通过 X% 的样本时，系统拦截了 Y% 的错误预测；相较最高置信度策略，错误流入后续流程的比例下降 Z%。"**

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 错误拦截率 | ≥ 80% | 所有错误预测中被标记为高风险的比例 |
| 自动覆盖率 | 60-80% | 所有样本中可自动通过的比例 |
| 选择性风险 | 显著低于基线 | 自动通过样本中的错误率 |
| 相较基线降低 | ≥ 30% | 错误流入后续流程比例 vs 最高置信度策略 |

## 4. 用户画像与场景

### 4.1 主要用户

| 用户 | 特征 | 需求 |
|------|------|------|
| **海洋地震学研究生** | 熟悉 OBS 数据，不熟悉 AI | 需要自动化的震相拾取，但能标记不可靠结果 |
| **海洋实验室工程师** | 负责数据处理流水线 | 需要一键部署的完整工具链，CPU 可运行 |
| **科考航次首席科学家** | 需要快速产出初步结果 | 希望自动处理大部分数据，仅复核高风险部分 |

### 4.2 核心用户故事

```
作为海洋地震学研究生，
我希望将OBS波形导入系统后自动获得P/S拾取结果和可靠性评估，
这样我可以只复核高风险样本，大幅减少人工工作量。

作为实验室工程师，
我希望用一行命令部署整个系统，
这样我不需要单独配置每个模型的复杂依赖。
```

## 5. 功能需求

### 5.1 功能模块总览

```
┌─────────────────────────────────────────────────────────┐
│                    OBS 可信AI调度层                       │
├───────────────┬───────────────┬─────────────────────────┤
│  数据质量检查  │  多模型引擎    │     可靠性决策层         │
│               │               │                         │
│ • 通道完整性   │ • 模型适配器   │ • 证据提取 (4类证据)      │
│ • 断点/削波   │ • 统一输出    │ • 风险评估 (L/M/H)       │
│ • SNR 估计    │ • 多模型比对   │ • 决策路由 (A/R/A)       │
│ • 频谱检查    │               │ • 原因码输出              │
├───────────────┴───────────────┴─────────────────────────┤
│                    可视化 & 交互层                        │
│                                                         │
│ • 波形 + 多模型拾取标记    • 风险报告面板                 │
│ • 事件统计 Dashboard       • 人工复核入口                 │
└─────────────────────────────────────────────────────────┘
```

### 5.2 功能详细描述

#### F1: 数据质量检查 (Data Inspector)

| 功能项 | 描述 | 优先级 |
|--------|------|--------|
| F1.1 通道完整性检查 | 检测是否缺失 Z/N/E/H 通道，是否与模型要求匹配 | P0 |
| F1.2 断点检测 | 检测波形中的间断/缺失段 (gap) | P0 |
| F1.3 削波检测 | 检测振幅是否超过量程 (clipping) | P0 |
| F1.4 SNR 估计 | 估算信号与噪声的比值 | P0 |
| F1.5 采样率兼容性 | 检测采样率是否与模型要求一致 | P1 |

#### F2: 多模型引擎 (Model Adapters)

| 功能项 | 描述 | 优先级 |
|--------|------|--------|
| F2.1 模型接入适配器 | 统一 PhaseNet、OBSTransformer 等模型的输入输出格式 | P0 |
| F2.2 统一 JSON 输出 | 所有模型输出标准化为 `{model, phase, time_s, score, window_id}` | P0 |
| F2.3 多模型并行推理 | 同时对同一段波形运行多个模型 | P0 |
| F2.4 模型版本追踪 | 记录每个预测的模型名称、版本和预处理版本 | P1 |

#### F3: 可靠性决策层 (Reliability Engine)

| 功能项 | 描述 | 优先级 |
|--------|------|--------|
| F3.1 四类证据提取 | 数据证据 + 单模型证据 + 多模型证据 + 物理约束证据 | P0 |
| F3.2 风险评分 | 综合证据计算 0-100 风险分数 | P0 |
| F3.3 风险等级映射 | LOW / MEDIUM / HIGH 三级 | P0 |
| F3.4 决策路由 | ACCEPT (自动通过) / ROUTE/FUSE (模型融合) / ABSTAIN (人工复核) | P0 |
| F3.5 原因码输出 | 每次决策附带结构化 reasons code | P0 |
| F3.6 冲突检测 | 多模型 P/S 拾取时间差异分析 | P0 |
| F3.7 物理约束检查 | P 在 S 之前、S-P 时间差合理 | P1 |

#### F4: 可视化面板 (Dashboard)

| 功能项 | 描述 | 优先级 |
|--------|------|--------|
| F4.1 波形展示 | 三通道波形图，叠加多模型 P/S 拾取标记 | P0 |
| F4.2 风险报告 | 当前样本的风险等级、原因码、各证据分数 | P0 |
| F4.3 人工复核界面 | 高风险样本波形 + 模型拾取 + 人工修正/确认入口 | P1 |
| F4.4 统计 Dashboard | 事件统计、风险分布、模型对比 | P1 |

### 6.2 数据流

```
输入: OBS 波形 (MiniSEED / HDF5 / NumPy)
    │
    ├── [Data Inspector] → quality_report.json
    │      通道完整性、断点率、削波率、SNR
    │
    ├── [Model Adapters] → predictions.json
    │      PhaseNet P/S 拾取 + OBSTransformer P/S 拾取
    │
    ├── [Evidence Engine] → evidence.json
    │      │
    │      ├── 数据证据: {gap_ratio, clipping_ratio, snr, ...}
    │      ├── 单模型证据: {peak_score, peak_width, ...}
    │      ├── 多模型证据: {time_diff, missing_detection, consensus}
    │      └── 物理证据: {p_before_s, sp_delta, ...}
    │
    └── [Reliability Engine] → reliability.json
           {risk_score, risk_level, action, reason_codes}
```

## 7. MVP 范围与边界

### 7.1 MVP 必须有 (P0)

| 模块 | 交付物 |
|------|--------|
| 数据质量检查 | 缺道、断点、削波、SNR 四项检测 |
| 模型接入 | OBSTransformer + PhaseNet，统一 JSON 输出 |
| 证据提取 | 数据证据 + 单模型证据 + 多模型分歧证据 |
| 可靠性引擎 | 规则版风险评分 (0-100) + 三级风险 + 三种动作 + 原因码 |
| 可视化 | 波形图 + 多模型标记 + 风险报告 |
| 评测 | 与单模型、最高置信度、简单投票的基线对比 |
| 工程 | README、一键复现脚本、依赖清单、开源协议 |
| 文档 | 4 页问题定义文档、本 PRD |

### 7.2 MVP 暂时不做 (P2+)

| 内容 | 原因 |
|------|------|
| 从零训练大型拾取模型 | 复用已有预训练模型 |
| 完整跨台站事件关联与震源定位 | MVP 聚焦拾取可靠性 |
| 覆盖所有 OBS 设备和数据格式 | MVP 先支持常见格式 |
| 用复杂黑盒模型替代简单风险规则 | 先用规则验证机制，再迭代 |
| 云端在线服务 | MVP 纯本地运行 |
| 三维地层反演 | 超出 MVP 范围 |

### 10.3 风险评分规则 (MVP 示意)

```python
def compute_risk_score(quality, predictions, physics_check):
    score = 0

    # 数据质量证据 (0-30分)
    if quality.missing_channels:
        score += 20
    if quality.gap_ratio > 0.1:
        score += 15
    if quality.clipping_ratio > 0.05:
        score += 10
    if quality.snr_db < 3.0:
        score += 15

    # 多模型证据 (0-40分)
    p_diff = abs_difference(predictions, phase='P')
    s_diff = abs_difference(predictions, phase='S')
    if p_diff > 1.0 or s_diff > 2.0:
        score += 30  # 严重分歧
    elif p_diff > 0.3 or s_diff > 0.5:
        score += 15  # 轻度分歧

    # 缺失检测 (0-20分)
    if has_missing_detection(predictions):
        score += 10

    # 物理约束 (0-10分)
    if not physics_check.p_before_s:
        score += 10
    if not physics_check.sp_within_range:
        score += 5

    return min(score, 100)
```

### 10.4 风险等级映射

| 风险分数 | 风险等级 | 动作 |
|----------|----------|------|
| 0 – 30 | LOW | ACCEPT — 自动通过 |
| 31 – 60 | MEDIUM | ROUTE/FUSE — 模型融合或选择更适配模型 |
| 61 – 100 | HIGH | ABSTAIN — 拒绝自动处理，进入人工复核 |

## 11. 评测指标与基线

### 11.1 必须对比的基线

| 方法 | 决策逻辑 | 说明 |
|------|----------|------|
| 单模型 (基准) | 固定采用 OBSTransformer 的结果 | 当前常见做法 |
| 最高置信度 | 每个样本选择 score 最高的模型结果 | 朴素的多模型策略 |
| 简单投票/平均 | 多数投票或时间中位数 | 传统集成方法 |
| **Trust Layer (我们)** | 质量 + 单模型 + 多模型 + 物理 → 接受/路由/拒绝 | 我们的创新 |

### 11.2 核心指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **错误拦截率 (Error Detection Rate)** | 所有错误预测中被标记为 HIGH 的比例 | ≥ 80% |
| **自动覆盖率 (Auto Coverage)** | 所有样本中被 ACCEPT 的比例 | 60-80% |
| **选择性风险 (Selective Risk)** | ACCEPT 样本中的错误率 | 显著低于基线 |
| **复核负担 (Review Burden)** | 需要人工查看的样本比例 | 可接受范围内 |
| **P 波 MAE** | P 波拾取时间平均绝对误差 | 不劣于单模型 |
| **S 波 MAE** | S 波拾取时间平均绝对误差 | 不劣于单模型 |

### 11.3 核心图表

> 风险-覆盖率曲线（Error-Retention Curve）是项目最重要的图表：
>
> X 轴：自动覆盖率 (Auto Coverage)
> Y 轴：错误拦截率 (Error Detection Rate)
>
> 我们的曲线应在所有覆盖水平上高于基线。
