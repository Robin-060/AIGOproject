# OBS Trust Layer Phase 2 / P3 实验与 Demo 报告

## 1. 摘要

P3 交付包括可读取数据组 `result.json` 的 Streamlit Demo、真实预训练模型噪声实验、失败案例分析和可追溯结果文件。样例 `obs_000000_trace0000` 可完成全链路分析：三模型在 P、S 两相位均形成共识并融合，总体风险为 8/100。

正式噪声实验使用 SeisBench 0.12.3 提供的公开 OBS 数据和预训练权重。在官方 `test` split 中固定选择 20 条四通道、同时含 P/S 标签的波形，并对同一批波形生成原始、10 dB、5 dB、2 dB 四档输入。实验真实运行 PhaseNet/geofon、PickBlue/obs-phasenet、OBSTransformer/obst2024，而非模拟模型输出。

结果显示：Trust Layer 在四档均未放行错误 P/S 对，安全处理率为 100%；L3 拦截率达到 100%，满足大于 60% 的验收项。但系统的代价也很明显：L0 拒绝率为 60%，L1–L3 拒绝率为 100%。因此当前版本更接近“安全优先的保守门控”，还不是高覆盖率自动处理系统。

20/20 对应的 95% Wilson 二项区间约为 83.9%–100%。这说明本轮结果支持“高于 60%”的验收判断，但不能据此宣称未来所有数据都能达到 100%。

## 2. 系统与 Demo

### 2.1 输入契约

Demo 接受数据组四合一 JSON，必需字段为 `sample_metadata`、`quality_report`、`model_profiles`、`model_predictions`。`adapter_statuses` 为可选字段，但缺失时模型适用性检查会将适配器视为不可用。系统会拒绝缺少必需区段、没有模型档案或没有预测的输入，并显示具体错误。

### 2.2 展示内容

页面包含总览、模型状态、风险分解、实验结果和完整 JSON 五个视图。模型状态包括加载、运行、输出可比性、适用性、共识角色和原因；风险图展示数据质量、单模型置信、多模型一致性和物理约束四类证据。

### 2.3 风险预算

当前启发式风险预算为：数据质量 0–30，单模型置信 0–15，多模型一致性 0–40，物理约束 0–15，总计 0–100。原流水线没有把数据质量证据送入可靠性汇总，导致风险恒为 0；本次实现补齐了该链路，并修复了最终对象的 JSON 序列化。

## 3. SeisBench 噪声鲁棒性实验

### 3.1 数据与模型

- 数据集：SeisBench `OBS`，分块 `201805`。
- 数据划分：仅使用官方 `test` split。
- 选样规则：四通道 `Z12H`、P/S 到时均非空、无 spike 标记，按事件、台站和 trace name 排序后固定取前 20 条。
- 标签来源：20 条中 P/S 均人工 7 条、P 自动/S 人工 8 条、P/S 均自动 4 条、P 人工/S 自动 1 条。逐条来源保存在结果 CSV。
- 单模型基线：OBSTransformer/obst2024。
- 最高置信度基线：每个相位从三个模型的候选中选择置信度最高者。
- Trust Layer：现有四证据流水线。
- 异构 PhaseNet：`geofon` 权重，避免与 PickBlue 的 `obs` PhaseNet 权重重复。
- 推理设备：CPU。当前 macOS 环境的 PyTorch MPS 后端不可实际使用，脚本会自动回退。

### 3.2 噪声与评估定义

同一条波形在每个噪声等级使用固定 SHA-256 派生种子，因此结果可重复，并且三个模型接收完全相同的噪声实现。

| 等级 | 定义 |
|---|---|
| L0 | 原始公开波形，不额外加噪 |
| L1 | 每通道加入 10 dB 高斯噪声 |
| L2 | 每通道加入 5 dB 高斯噪声 |
| L3 | 每通道加入 2 dB 高斯噪声 |

P 波正确容差为 0.5 s，S 波正确容差为 1.0 s。P/S 两者都在容差内才算正确。如果模型或 Trust Layer 没有输出完整 P/S 对，记为拒绝；输出了错误 P/S 对则记为不安全错误。

图中“拦截/安全处理率”定义为：正确输出或安全拒绝所占比例，即 `1 - 不安全错误数 / 20`。报告同时给出准确率和拒绝率，避免用高拒绝率掩盖覆盖率下降。

### 3.3 真实推理结果

| 噪声 | 方法 | 正确 | 拒绝 | 不安全错误 | 安全处理率 |
|---|---|---:|---:|---:|---:|
| L0 | OBSTransformer | 18 | 0 | 2 | 90% |
| L0 | 最高置信度 | 18 | 0 | 2 | 90% |
| L0 | Trust Layer | 8 | 12 | 0 | 100% |
| L1 | OBSTransformer | 1 | 15 | 4 | 80% |
| L1 | 最高置信度 | 2 | 15 | 3 | 85% |
| L1 | Trust Layer | 0 | 20 | 0 | 100% |
| L2 | OBSTransformer | 0 | 19 | 1 | 95% |
| L2 | 最高置信度 | 0 | 18 | 2 | 90% |
| L2 | Trust Layer | 0 | 20 | 0 | 100% |
| L3 | OBSTransformer | 0 | 19 | 1 | 95% |
| L3 | 最高置信度 | 0 | 18 | 2 | 90% |
| L3 | Trust Layer | 0 | 20 | 0 | 100% |

补充指标已经写入 `noise_summary_seisbench.csv`，包括覆盖率、选择性准确率、不安全输出率、P/S 到时 MAE 与安全处置率的 Wilson 95% 区间。最关键的对照是：Trust Layer 在 L0 的覆盖率为 40%、已输出样本准确率为 100%；在 L1–L3 的覆盖率为 0%，因此只能得出“没有放行错误完整对”，不能得出“高噪下仍能准确拾取”。

完整结果：

- `noise_predictions_seisbench.json`：每个模型的实际 P/S 时间和置信度。
- `noise_records_seisbench.csv`：逐样本、逐等级、逐方法结果及标签来源。
- `noise_summary_seisbench.csv`：汇总指标。
- `noise_curve.png`：安全处理率曲线。

### 3.4 图表解读

L0 上，两个基线各放行 2 个错误对，而 Trust Layer 没有不安全输出，说明多模型共识和拒绝机制确实提供了安全收益。L1–L3 上，基线仍会偶尔给出错误完整对；Trust Layer 全部拒绝，因此安全处理率保持 100%。

不过，100% 安全处理率不等于 100% 检测准确率。Trust Layer 在 L1–L3 的正确自动输出为 0，覆盖率也为 0。当前策略的主要价值是“在高噪下不乱给答案”，而不是“在高噪下仍准确拾取”。下一阶段优化目标应是保持不安全错误接近 0 的同时提高 L0/L1 自动覆盖率。

## 4. 失败案例主要发现

本轮 20 条正式实验中，Trust Layer 没有漏放错误，因此没有真实的 Trust Layer 漏拦样本。两个基线共出现多个可追溯的不安全输出，例如：

- `XO.LA33..HH.2018.05.21.19.58.59` 的 L0：真值 S=70.45 s，基线输出 S=46.09 s。
- `XO.LT07..HH.2018.05.18.22.11.25` 的 L3：最高置信度 P=14.16 s，而真值为 44.99 s。
- `XO.LT04..HH.2018.05.25.08.40.15` 的 L1：基线 P=35.84 s，而真值为约 44.99 s。

详细文档继续保留三类构造失效机制，用于说明在更大样本中可能出现的共同误拾、坏数据高置信和真值争议。不能把这些构造案例表述为本轮真实观察到的 Trust Layer 漏拦。

## 6. 局限性

1. 样本量仅 20，置信区间较宽，适合作为比赛 Demo 和初步证据，不足以形成领域通用结论。
2. 仅 7 条样本的 P/S 都是人工标签，其余至少一个相位来自自动标签；标签来源已保留，后续应在纯人工子集或更大分块复核。
3. L1–L3 使用人工添加的高斯噪声，不能覆盖拖网、海流、机械脉冲等真实 OBS 噪声类型。
4. Trust Layer 在 L1–L3 全拒绝，安全性高但覆盖率为零，策略仍需校准。
5. 风险权重和阈值为 `heuristic_v0.1`，尚未在独立开发集上优化。
6. 物理规则只检查 P/S 时间顺序与间隔，不检查波形形态和事件关联。
7. 经典 STA/LTA 在这 20 个正事件窗口上的事件召回率为 50%，平均每窗口产生 5.65 个不匹配触发；当前样本没有带标签的纯噪声窗口，因此不报告其假阳性率。
8. 本机 CPU 工程测量证明当前模型可运行，但不等价于量化或剪枝，也不能外推到所有笔记本。
9. 项目未接触南海受限数据、未开展实地科考和真实用户实验；“降低 90% 人工工作量”仍是未来待验证目标。

## 7. 工程补充

Demo 现支持 CSV、MiniSEED 和 SEG-Y 波形读取；提供去趋势、Taper、带通、可选陷波和归一化预处理，并叠加显示三模型 P/S 拾取位置。事件状态使用透明规则标记为“地震候选、低质量数据、噪声或待复核”，不把该规则表述成训练完成的 AI 分类器。

CPU 实测使用一条 150 秒公开 OBS 波形、热缓存和 CPU：PhaseNet、PickBlue、OBSTransformer 的状态字典规模分别约 1.03、1.03、1.43 MiB；本机中位推理时间约为 6.1、6.3、21.4 ms，Trust Layer 本身中位耗时约 0.03 ms。该数字仅用于证明本地运行可行性，不是跨设备性能承诺。

## 8. 结论

P3 已从固定模拟曲线升级为公开 OBS 波形上的真实预训练模型实验。当前证据支持一个克制的结论：Trust Layer 在这 20 条样本及四档噪声中避免了基线出现的不安全 P/S 输出，但通过大量拒绝换取了安全性。下一步应扩大纯人工测试样本、加入真实海洋噪声，并优化风险阈值以提高覆盖率。
