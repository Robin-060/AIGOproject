# DS 判定汇总（v1.5 新口径）

> C 口径调整（2026-08-31）：DS 不是"必须全绿的考试"，而是"系统能力的五个问题"。
> 如实报告成立、失败及边界；不追求 5/5。

## 五个问题与最终判定

| DS | 问题（新口径） | 判定 | 依据 |
|---|---|---|---|
| DS1 | Trust Layer 是否真的优于简单投票？ | ⚠️ **NOT_EVALUABLE@50% + 总体天花板点并列、S 相显著更差**（不强求） | 严格 FUSE 门槛后天花板 45.6%，50% 点位不可达 → NOT_EVALUABLE；总体天花板补充比较 Δ=+1.2pp，95% CI 含 0 → INCONCLUSIVE；**S 相在自身 45.45% 天花板处 Δ=+3.39pp，CI [+0.90,+5.96]，显著差于 Voting（EXP15 负结果，如实记录，未通过调参修饰）**。诚实边界：**同域、模型性能接近、样本简单时，复杂调度的边际收益有限**；覆盖率天花板本身也是代价（54.2%→45.6%，−8.6pp 换取 FUSE 质量） |

## 附加发现（支撑判定）

1. 模型身份错位（geofon 指纹破案）→ model_registry 修正
2. "完全一致也会错"（DS3 副产品）→ FUSE 门槛的实证动机
3. OBSTransformer 置信度过度自信（0.9→实际 87%）→ 校准的直接对象
4. STA/LTA 弱相关（46.7% vs 60.9%）→ 首个被 Evidence Admission Rule 拒绝的候选
5. FUSE 门第 4.5 步绕过被发现并堵住（低置信共识不再绕过门槛）→ 天花板 54.2%→45.6%，
   50% 预声明点位不可达，NOT_EVALUABLE 纪律确立

## 报告原则

- 每个判定附出处文件（results/ 下对应 CSV/JSON）
- 负结果与边界一律保留，不删不改（append-only）

  天花板补充比较必须标注"补充（天花板 X%）"字样
